Case note · GIS decision support

Turning accident locations into explorable risk zones and routes.

Accident pointsBuffersRisk zonesRoute scores

The need

Point locations alone make it difficult to see where incidents concentrate or how a planned route intersects higher-risk areas.

The approach

I built a browser-based map that groups overlapping accident buffers, scores route sections and exposes radius, layer and endpoint controls.

The value

The interface turns spatial records into an accessible tool for exploring clusters, comparing routes and discussing where attention may be needed.

Public demonstration using browser-based geospatial analysis; risk scores support exploration and do not replace formal safety assessment.

Case note · Statistical modelling

Comparing forecasting approaches without losing sight of time.

ExploreBuild baselinesFit modelsValidate forward

The need

Forecasting choices are difficult to compare when methods are presented in isolation or evaluated with validation that ignores temporal order.

The approach

I organized reproducible R and Python examples across baseline, ARIMA/SARIMA, dynamic regression, state-space and volatility models.

The value

The repository makes model assumptions and comparisons easier to inspect while reinforcing time-aware validation and reproducible analysis.

Open learning repository; notebooks demonstrate methods and are not forecasts for a live operational system.

Case note · Applied machine learning

Making SDG contribution mapping faster and more consistent.

Project indicatorsText embeddingsSimilarity scoresHuman review

The need

Institutional reporting required teams to connect many project indicators with the most relevant SDG indicators.

The approach

I used Python and the paraphrase-MiniLM-L6-v2 model to rank semantic similarity, producing candidate matches and scores.

The value

The model provided a structured first pass for expert review—supporting consistency without pretending that automated matching replaces programme judgment.

Representative institutional work; the model assisted human review and did not make final reporting decisions.

Case note · Reporting automation

Producing many consistent reports from one trusted dataset.

Source dataParametersRenderQuality check

The need

Segmented reporting creates repetitive work and avoidable inconsistencies when each geography or group is prepared as a separate document.

The approach

I built an R and Quarto workflow that applies parameters to one analysis and renders each required report through the same documented process.

The value

Teams can update a complete reporting set more efficiently while keeping calculations, structure and quality checks consistent across outputs.

Open demonstration workflow; the linked repository includes the reproducible example and implementation pattern.
